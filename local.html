LoopForge Local · 面向个人开发者 · 无需服务端

让现有编程助手，
按一套工作流
完成开发任务。

已经在用 Claude Code、CodeBuddy、Codex 或 Cursor？LoopForge Local 把内置的开发工作流装进你的 IDE / CLI：先理解需求，再设计和实现，中大型任务分角色审查与测试，并将过程记录保存到项目中。

安装到我的编程助手 →我要团队平台，返回介绍

不是平台的本地部署版

这里的“Local”指运行在编程助手里的工作流，不是把平台搬到本机。它不提供平台的 Web 工作台、可视化 SOP 编排和团队共享审批记录。

平台本身也可以部署在本机。平台 SOP 导出到 Local 独立执行尚未实现，两者不能当成同一套能力的不同部署方式。

团队需要共享流程和验收？

请选择 LoopForge 平台：在 Web 工作台中管理需求、编排 SOP、配置 Agent 角色、检查运行证据，并由团队成员完成关键审批。

在你原来的工具里工作

不是换一个 Agent，
而是给它一套做事的方法。

小改动走精简路径：理解 → 实现 → 自检 → 交付。中大型任务启用下面的分阶段工作流，避免为简单任务增加不必要的流程。

澄清并确认→设计→实现→独立审查→测试→交付
01 / 先确认

目标和边界说清楚

中大型任务先确认范围、排除项、关键决策和验收标准，再进入设计与实现。

02 / 分角色

减少同一上下文的自审偏差

设计、实现、审查和测试分阶段、分职责完成。简单任务保留精简的单角色路径。

03 / 留证据

过程留在项目里

需求、方案、审查意见、测试结果和交付总结保存到 artifacts/，流程中断后可以恢复。

安装到目标项目 · 默认 Classic 工作流

选择你已有的编程助手。

需要 Node.js 20+、Python 3.8+，以及已可使用的编程助手。在目标项目目录运行安装命令，再到对应助手中启动工作流。Local 不附带模型额度，使用你原有工具的模型配置。

Claude Code

npx -y loopforge-cli@latest install claude

# 然后在 Claude Code 中输入
/start-devflow "为订单列表增加状态筛选，并补充接口测试"

npx -y loopforge-cli@latest install codebuddy
