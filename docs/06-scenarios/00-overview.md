# 场景总览

> **真实场景 · 总览** · 8 个在开源版 LoopForge 上真实跑过的使用场景。截图都是真实页面，每一步都可以照着在自己的项目里做一遍。

## 这一章怎么用

每个场景都按同样的结构写：解决什么问题、直接复制的指令、每一步应该看到什么、实测结果、以及它证明不了什么。建议从 S01 开始，它不需要接代码仓库，10 分钟就能跑完。

| 编号 | 你想做什么 | 跟着做完你会得到 |
| --- | --- | --- |
| **S01** | 用一句话让 AI 做一个小工具 | 可运行的代码、交互网页、3 条通过的测试 |
| **S02** | 和同事在同一个会话里接力 | 同一份聊天历史、同一个需求和 PR |
| **S03** | 把团队的做事方法存成资产 | 可复用的角色、Skill、SOP、MCP |
| **S04** | 用 @ 调用已有资产 | 按清单检查后的结论和阻塞项 |
| **S05** | 让 AI 定时干活，7×24 小时运行 | 到点自动启动的 SOP 运行 |
| **S06** | 看团队花了多少、交付了多少 | 按项目、成员拆开的用量和交付 |
| **S07** | 在本地 IDE 里使用平台 | 本地 Agent 能查项目、启动流程 |
| **S08** | 把正式需求交给 SOP 跑完 | 固定步骤、人工拍板、每一步留痕可查 |

## 两种工作方式

* **在 AI 工作台对话**：适合探索、写方案、做小工具、快速修改。对应 S01–S04。
* **运行 SOP 标准流程**：适合正式需求，需要固定的评审、测试和人工确认。对应 S05、S08。

两种方式共用同一个项目、同一张需求单，可以先聊清楚，再交给 SOP 执行。

> **在你自己的部署里照做**：截图里的名字来自我们的演示项目「公共案例 · 发布就绪实验室」，你的部署里一开始没有。S01 会生成一张需求单，S03 会创建角色、Skill 和 SOP，后面的 S04、S05、S08 都用它们。按顺序照着指令做，你会在自己的项目里得到同名的东西。

> 开始之前，先完成 [配置模型 API Key](../01-getting-started/06-configure-api-key.md)，确保你选的执行器有可用凭据。
